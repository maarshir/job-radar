# Настройка

## Что нужно

- n8n 2.x, где узлам Code разрешён модуль `node:sqlite`. Подойдёт n8n из этого `docker-compose.yml` или уже работающий n8n с такой же настройкой, например из content-factory.
- Бот Телеграма (создаётся у @BotFather). Ему нужно один раз написать /start из чата, куда придут вакансии.
- Ключ нейросети с совместимым с OpenAI интерфейсом: Groq, GigaChat через gpt2giga или другой.

Публичный адрес и вебхуки не нужны: сбор запускается каждые 10 минут, почта проверяется сама, сообщения бот отправляет сам. n8n в Докере с `restart: unless-stopped` работает круглосуточно и поднимается после перезагрузки сервера.

## Запуск n8n

Если n8n уже работает, этот шаг пропускается.

```
cp .env.example .env
# заполнить N8N_ENCRYPTION_KEY (openssl rand -hex 32)
docker compose up -d
```

n8n слушает только localhost:5678. С телефона или другого компьютера его удобно открывать через туннель SSH: `ssh -L 5678:localhost:5678 пользователь@сервер`, затем http://localhost:5678.

## Конвейер

1. Импорт. В n8n: Workflows, Import from File, `workflows/collect.json`. Или на сервере из папки репозитория:
   ```
   docker compose cp workflows/collect.json n8n:/tmp/collect.json
   docker compose exec n8n n8n import:workflow --input=/tmp/collect.json
   ```
2. Учётные данные. В узле «Нейросеть» учётные данные OpenAI с ключом и Base URL (для Groq `https://api.groq.com/openai/v1`), в узле «Отправка» учётные данные Telegram с токеном бота. Если они уже созданы для другого конвейера, их можно выбрать из списка.
3. Узел «Настройки»:
   - `LLM_MODEL` и тот же адрес в `LLM_BASE_URL`;
   - `CHAT_ID`: номер чата, куда присылать вакансии (свой номер покажет бот @userinfobot);
   - `MIN_SCORE`: порог оценки по умолчанию, 7. Если порог задан кнопкой в боте, действует он;
   - `MAX_ITEMS`: сколько вакансий за запуск уходит в нейросеть, остальные придут в следующий раз;
   - `JR_DB_PATH`: путь к журналу внутри контейнера.
4. Запустить вручную кнопкой Execute workflow и проверить, что вакансии пришли. Затем включить конвейер, он запускается каждые 10 минут.

Первый запуск соберёт всё свежее за четыре дня, дальше приходят только новые вакансии.

## Источники

Список в `src/sources.json`, после правки `npm run build` и повторный импорт конвейера.

- `trudvsem`: «Работа России», портал Роструда. Открытый API без ключа и входа, описание на trudvsem.ru/opendata/api. В `params` поле `text` и любые параметры API; `region` из 13 цифр (Москва `7700000000000`), без него вся Россия. Проверить, что API отвечает с вашего сервера:
  ```
  curl -s -o /dev/null -w "%{http_code}\n" "https://opendata.trudvsem.ru/api/v1/vacancies?text=python&limit=1"
  ```
  Ответ `200` значит, всё в порядке. Если вместо него ошибка или ожидание без конца, портал не пускает адрес сервера; тогда этот источник работает только с сервера в России.
- `hh`: поиски hh.ru по RSS. Открытый API hh.ru для соискателей закрыт с конца 2025 года, RSS с сервера тоже может не отдаваться, поэтому список пуст, а hh.ru подключается через почту (ниже).
- `telegram`: публичные каналы, имя без @. Читается страница `t.me/s/<канал>`, там около 20 последних постов; если у канала выключен предпросмотр, страница пустая и канал ничего не даёт.
- `rss`: любые ленты RSS или Atom, полный адрес в `url`.

Ключевые и стоп-слова в `src/filter.config.json`, описание кандидата и ссылки для писем в `src/profile.md`, сам промпт в `prompts/score.md`.

## Почта: hh.ru, SuperJob, Хабр Карьера

Сайты сами присылают новые вакансии по сохранённому поиску. Конвейер читает эти письма и достаёт из них ссылки на вакансии, так что hh.ru остаётся в сборе без API и без обхода защиты.

1. На каждом сайте сохранить поиск и включить уведомления о новых вакансиях на почту, как можно чаще: на hh.ru это «Автопоиск» с рассылкой, на SuperJob и Хабр Карьере подписка на поиск.
2. В почте создать папку `Vacancies` на верхнем уровне (не внутри «Входящих») и фильтр «любое из условий»: «От кого» содержит `hh.ru`, `superjob.ru` или `habr`, переместить в эту папку. Латинское имя нужно потому, что папку с русским названием IMAP-сервер mail.ru узлу не отдаёт. Конвейер отмечает их прочитанными, остальная почта не трогается.
3. Для mail.ru в настройках безопасности создать пароль для внешних приложений с доступом по IMAP. Обычный пароль не подойдёт.
4. В n8n в узле «Почта» создать учётные данные IMAP: пользователь: адрес почты, пароль: пароль для приложений, сервер `imap.mail.ru`, порт 993, SSL включён. Включить узел (долгое нажатие или клавиша D на выделенном узле) и нажать Publish.

При проверке кнопкой Execute step узел ждёт новое письмо: старые непрочитанные он не берёт. Чтобы проверить сразу, перенесите письмо от hh.ru в папку `Vacancies`, пока узел ждёт.

Вакансии из писем ждут в очереди и проходят оценку при ближайшем запуске, то есть приходят в Телеграм в пределах 10 минут после письма. Если ссылки из писем какого-то сайта не находятся, стоит посмотреть, куда ведут ссылки в письме, и добавить шаблон в `src/mail.js`.

## Бот: проверка, статистика, порог

Второй конвейер `workflows/bot.json` отвечает на кнопки в том же боте. Кнопки появляются после команды /start:

- **Есть ли вакансии:** работает ли сбор (когда был последний запуск, какие источники не ответили, были ли ошибки нейросети) и что нашлось за сутки. Если подходящих нет, бот предлагает показать вакансии ниже порога за неделю.
- **Статистика:** сколько вакансий собрано, оценено нейросетью, подошло, ниже порога и отсеяно фильтром: сегодня, за неделю и всего.
- **Порог:** с какой оценки присылать вакансии. Новый порог сразу действует в сборе. Если порог снижен, бот предлагает показать вакансии за неделю, которые не прошли по прежнему.

Настройка:

1. Импортировать конвейер так же, как сбор:
   ```
   docker compose cp workflows/bot.json n8n:/tmp/bot.json
   docker compose exec n8n n8n import:workflow --input=/tmp/bot.json
   ```
2. В узле «Настройки бота» заполнить `BOT_TOKEN` (токен того же бота от @BotFather) и `CHAT_ID` (тот же, что в сборе). Бот отвечает только этому чату.
3. Нажать Publish и написать боту /start.

Бот без вебхука и публичного адреса: раз в 10 секунд конвейер спрашивает у Телеграма новые сообщения и ждёт ответа до 5 секунд, поэтому ответ приходит за несколько секунд. Удачные запуски не сохраняются, чтобы не забивать список Executions. Если бот совсем молчит, значит, не работает сам n8n или конвейер бота не опубликован.

## Журнал

SQLite в томе n8n, таблица `vacancies`: ссылка, заголовок, источник, статус (`collected`, `rejected`, `matched`), причина отказа и оценка. Посмотреть, почему вакансии отсеиваются:

```
docker compose exec n8n sh -c "node -e \"const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('/home/node/.n8n/job-radar.sqlite');console.table(db.prepare('SELECT reason, COUNT(*) n FROM vacancies GROUP BY reason ORDER BY n DESC').all())\""
```

Если нейросеть не ответила, запись удаляется и вакансия придёт в следующий запуск.
