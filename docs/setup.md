# Настройка

## Что нужно

- n8n 2.x, где узлам Code разрешён модуль `node:sqlite`. Подойдёт n8n из этого `docker-compose.yml` или уже работающий n8n с такой же настройкой, например из content-factory.
- Бот Телеграма (создаётся у @BotFather). Ему нужно один раз написать /start из чата, куда придёт подборка.
- Ключ нейросети с совместимым с OpenAI интерфейсом: Groq, GigaChat через gpt2giga или другой.

Публичный адрес и вебхуки не нужны: конвейер запускается по расписанию и сам отправляет сообщения.

## Запуск n8n

Если n8n уже работает, этот шаг пропускается.

```
cp .env.example .env
# заполнить N8N_ENCRYPTION_KEY (openssl rand -hex 32)
docker compose up -d
```

n8n слушает только localhost:5678. С телефона или другого компьютера его удобно открывать через туннель SSH: `ssh -L 5678:localhost:5678 пользователь@сервер`, затем http://localhost:5678.

## Конвейер

1. Импорт. В n8n: Workflows, Import from File, `workflows/collect.json`. Или на сервере из папки репозитория:
   ```
   docker compose cp workflows/collect.json n8n:/tmp/collect.json
   docker compose exec n8n n8n import:workflow --input=/tmp/collect.json
   ```
2. Учётные данные. В узле «Нейросеть» учётные данные OpenAI с ключом и Base URL (для Groq `https://api.groq.com/openai/v1`), в узле «Отправка» учётные данные Telegram с токеном бота. Если они уже созданы для другого конвейера, их можно выбрать из списка.
3. Узел «Настройки»:
   - `LLM_MODEL` и тот же адрес в `LLM_BASE_URL`;
   - `CHAT_ID`: номер чата, куда присылать подборку (свой номер покажет бот @userinfobot);
   - `MIN_SCORE`: порог оценки, по умолчанию 7;
   - `MAX_ITEMS`: сколько вакансий за запуск уходит в нейросеть, остальные придут в следующий раз;
   - `JR_DB_PATH`: путь к журналу внутри контейнера.
4. Запустить вручную кнопкой Execute workflow и проверить, что подборка пришла. Затем включить конвейер, по умолчанию он запускается раз в четыре часа.

Первый запуск соберёт всё свежее за четыре дня, дальше приходят только новые вакансии.

## Источники

Список в `src/sources.json`, после правки `npm run build` и повторный импорт конвейера.

- `hh`: поиски hh.ru. В `params` те же параметры, что в адресной строке поиска на сайте (`text`, `experience`, `schedule`, `area` и другие). Конвейер берёт RSS этого поиска. Открытый поиск через api.hh.ru с весны 2026 года без токена приложения не работает, а RSS отдаётся без входа.
- `telegram`: публичные каналы, имя без @. Читается страница `t.me/s/<канал>`, там около 20 последних постов; если у канала выключен предпросмотр, страница пустая и канал ничего не даёт.
- `rss`: любые ленты RSS или Atom, полный адрес в `url`.

Ключевые и стоп-слова в `src/filter.config.json`, описание кандидата для нейросети в `src/profile.md`, сам промпт в `prompts/score.md`.

## Журнал

SQLite в томе n8n, таблица `vacancies`: ссылка, заголовок, источник, статус (`collected`, `rejected`, `matched`), причина отказа и оценка. Посмотреть, почему вакансии отсеиваются:

```
docker compose exec n8n sh -c "node -e \"const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('/home/node/.n8n/job-radar.sqlite');console.table(db.prepare('SELECT reason, COUNT(*) n FROM vacancies GROUP BY reason ORDER BY n DESC').all())\""
```

Если нейросеть не ответила, запись удаляется и вакансия придёт в следующий запуск.
